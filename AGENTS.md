# CordWipe project instructions

Follow the global instructions. These additional rules govern public-facing writing.

## Public copy
- Write the README and store listing for someone deciding whether to install and use CordWipe, not for the project owner, agents, or reviewers. Lead with the benefit, working install path, how to use it, and support.
- Use concise, natural English. Do not put internal progress reports in public copy: PR/issue status, work awaiting approval, comparisons of development and published versions, test summaries, release gates, or details of agent coordination. Put those in PRs, Issues, release notes, or reviewer-specific documents.
- Keep public installation links accurate and usable. Avoid version/status commentary in the README; give the version on the download or release page. When shipping and documented behavior diverge, fix the relevant link or description rather than add a long disclaimer.
- Keep essential facts: permanent deletion, Discord account-automation risk, meaningful limitations, privacy policy access, and required Undiscord attribution. State each warning briefly, without repeating it across sections. Do not hide data access or claim capabilities not verified.
- Before committing user-facing documentation, read the whole affected section as an end user. Remove obsolete wording, excessive qualifications, repetition, and technical details that don't help someone use the product.
